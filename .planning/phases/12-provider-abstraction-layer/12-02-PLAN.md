Update `scripts/lib/common.sh` with provider-aware preflight logic.

**1. Add a `check_provider()` function** before `preflight_checks()`:

The function must:
- Read `CLUSTER_PROVIDER` from environment (default: `kinder`)
- Determine if the provider was explicitly set by checking `CLUSTER_PROVIDER_EXPLICIT` env var (set to `true` by Makefile when user passes CLUSTER_PROVIDER=xxx on command line -- this will be added in Phase 14 when scripts consume the variable; for now the function supports it)
- If the provider binary exists (`command -v "$provider"`): return 0 (success)
- If explicitly requested provider is missing: `log_error` with install instructions and return 1 (hard fail). Messages:
  - For kinder: "kinder is not installed. Install from https://github.com/kubernetes-sigs/kinder"
  - For kind: "kind is not installed. Install from https://kind.sigs.k8s.io/"
- If default provider (kinder) is missing and NOT explicit:
  - Check if stdin is a TTY (`[ -t 0 ]`). If not a TTY (CI/piped), log_error and return 1 (no prompt in non-interactive environments)
  - If TTY: `log_warn "kinder is not installed (default provider)."` then prompt `"  Fall back to kind? (y/n) "`
  - If user answers y/Y AND `command -v kind` succeeds: `export CLUSTER_PROVIDER=kind`, log_info "Using kind as fallback provider", return 0
  - If user declines or kind also missing: return 1

<task type="auto">
  <name>Task 2: Add CLUSTER_PROVIDER to parse_args for explicit detection</name>
  <files>scripts/lib/common.sh</files>
  <action>
The Makefile exports `CLUSTER_PROVIDER` as an environment variable to scripts. To distinguish between "user explicitly set CLUSTER_PROVIDER=kind" and "using the default kinder", we need a mechanism.

**Approach:** The Makefile already sets `CLUSTER_PROVIDER` via environment. Add a simple heuristic in `check_provider()`: if `CLUSTER_PROVIDER` is set in the environment AND its value is NOT "kinder" (the default), treat it as explicit. This avoids needing a separate `CLUSTER_PROVIDER_EXPLICIT` variable for the common case.

Update `check_provider()` logic:
- `local provider="${CLUSTER_PROVIDER:-kinder}"`
- `local is_explicit=false`
- If `CLUSTER_PROVIDER` is set (non-empty) AND value is not "kinder": `is_explicit=true`
- Also support `CLUSTER_PROVIDER_EXPLICIT=true` as an override for when someone explicitly sets `CLUSTER_PROVIDER=kinder` (edge case, future-proofing)

This way:
- `make up` (no variable) -> CLUSTER_PROVIDER=kinder from Makefile default -> env has "kinder" -> not explicit -> fallback prompt available
- `make up CLUSTER_PROVIDER=kind` -> env has "kind" -> explicit -> hard fail if missing
- `CLUSTER_PROVIDER_EXPLICIT=true make up` -> forced explicit -> hard fail if missing

This is already covered by the check_provider implementation in Task 1. This task ensures the explicit detection heuristic is correctly implemented within that function. If Task 1 already handles this correctly, verify and confirm -- no additional file changes needed.
  </action>

4. CLUSTER_PROVIDER=kinder + CLUSTER_PROVIDER_EXPLICIT=true -> explicit -> hard fail if missing
