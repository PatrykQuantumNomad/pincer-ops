<task type="auto">
  <name>Task 2: Add CLUSTER_PROVIDER variable and update Makefile targets</name>
  <files>Makefile</files>
  <action>
Update the Makefile with provider abstraction plumbing.

**1. Add provider variables in the Constants section (after ARGOCD_ADDR):**

```makefile
# Provider selection (kinder default, kind opt-in)
CLUSTER_PROVIDER ?= kinder
PROVIDER_BIN     := $(CLUSTER_PROVIDER)
PROVIDER_CONFIG  := cluster/$(CLUSTER_PROVIDER)-config.yaml
```

**2. Update provider-aware targets to export CLUSTER_PROVIDER:**

Provider-aware targets (per user decision): `up`, `down`, `reset`, `status`, `sync`, `load-image`, `doctor`.

For `up`/`bootstrap`: Pass CLUSTER_PROVIDER to bootstrap.sh via environment variable:
```makefile
bootstrap:
	@CLUSTER_PROVIDER=$(CLUSTER_PROVIDER) ./scripts/bootstrap.sh
```

For `down`/`teardown`: Pass CLUSTER_PROVIDER to teardown.sh:
```makefile
teardown:
	@CLUSTER_PROVIDER=$(CLUSTER_PROVIDER) ./scripts/teardown.sh
```

For `clean`: Same pattern:
```makefile
clean:
	@CLUSTER_PROVIDER=$(CLUSTER_PROVIDER) ./scripts/teardown.sh --clean
```

For `load-image`: Replace hardcoded `kind` with `$(PROVIDER_BIN)`:
```makefile
	@$(PROVIDER_BIN) load docker-image $(IMAGE) --name $(CLUSTER_NAME)
	@echo "Loaded $(IMAGE) into cluster $(CLUSTER_NAME) via $(PROVIDER_BIN)"
```

For `status` and `sync`: These use kubectl/argocd (not the provider binary directly), but export CLUSTER_PROVIDER for consistency so downstream scripts can detect the provider if needed. No changes needed to the actual commands -- kubectl works identically regardless of provider.

For `version`: Add kinder version line, update kind line:
```makefile
	@echo -n "Kinder:      "; kinder version 2>/dev/null || echo "not installed"
	@echo -n "KIND:        "; kind version 2>/dev/null || echo "not installed"
```

**3. Update `make help` target to show provider info:**

Add these lines after the "Usage:" line in the help target:
```makefile
	@echo "Provider: $(CLUSTER_PROVIDER) (override with CLUSTER_PROVIDER=kind)"
	@echo ""
```

**4. Add a `doctor` target placeholder** (referenced in provider-aware list per user decision):
```makefile
.PHONY: doctor
doctor: ## Check cluster health for current provider
	@echo "Provider: $(CLUSTER_PROVIDER)"
	@echo -n "$(PROVIDER_BIN): "; command -v $(PROVIDER_BIN) >/dev/null 2>&1 && echo "installed" || echo "NOT INSTALLED"
	@echo -n "Docker: "; docker info >/dev/null 2>&1 && echo "running" || echo "NOT RUNNING"
	@echo -n "kubectl: "; command -v kubectl >/dev/null 2>&1 && echo "installed" || echo "NOT INSTALLED"
	@echo -n "Cluster: "; $(PROVIDER_BIN) get clusters 2>/dev/null | grep -q $(CLUSTER_NAME) && echo "$(CLUSTER_NAME) exists" || echo "$(CLUSTER_NAME) not found"
```

Place this in the Operations section.

Do NOT modify provider-agnostic targets: `validate`, `test`, `check`, `seal`, `logs`, `pods`.
  </action>
  <verify>
Run `make help` -- confirm output shows "Provider: kinder" and the doctor target appears in the list.

Run `grep -c 'CLUSTER_PROVIDER' Makefile` -- confirm the variable appears in all provider-aware targets.
Run `grep 'PROVIDER_CONFIG' Makefile` -- confirm it resolves to `cluster/$(CLUSTER_PROVIDER)-config.yaml`.
  </verify>
  <done>

  </done>
