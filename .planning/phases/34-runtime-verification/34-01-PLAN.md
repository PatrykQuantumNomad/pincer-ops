Create `scripts/verify-supervisor.sh` following the exact structure of `scripts/verify-networkpolicy.sh`. The script must be executable (chmod +x). Include the standard file header comment block matching the style in `verify-networkpolicy.sh`.

**Script structure:**

1. **Preamble**: `set -euo pipefail`, source `lib/common.sh`, set CLUSTER_PROVIDER/CLUSTER_NAME defaults, trap for INT/TERM, PASSED/FAILED counters, local `run_test` function (identical to verify-networkpolicy.sh).

2. **Pre-flight checks** (exit 1 if any fail):
   - Cluster exists: `${CLUSTER_PROVIDER} get clusters` contains `${CLUSTER_NAME}`
   - Sandbox pod running: `kubectl get pod openclaw-sandbox -n openshell` exists and status is Running
   - Registration Job completed: `kubectl get job -n openshell -l argocd.argoproj.io/hook=PostSync -o jsonpath='{.items[0].status.succeeded}'` returns `1`. If Job has not completed, log a warning that policy may not be registered and continue (do not hard-fail -- the Job may not exist yet on first sync).
   - Log: "Pre-flight checks passed (cluster: NAME, pod: openclaw-sandbox)"

3. **Test 1 -- Supervisor is PID 1** (VERT-01):
   `kubectl exec -n openshell openclaw-sandbox -- sh -c 'cat /proc/1/cmdline | tr "\0" " "'`
   Check output contains `openshell` (the supervisor binary path). Pass if found, fail if not.

4. **Test 2 -- Child process exists (uid 1000)** (VERT-01):
   `kubectl exec -n openshell openclaw-sandbox -- sh -c '...'` where the inner script iterates `/proc/*/status` to find a process with Uid 1000 (non-PID-1). Output `child_pid=PID` if found. Pass if a child PID is found, fail otherwise. Store the child PID discovery logic in a shell variable `FIND_CHILD` that can be reused across tests.

   Use this child PID finder (reused in tests 3, 5):
   ```
   FIND_CHILD='
   for pid in $(ls /proc/ | grep -E "^[0-9]+$" | sort -n); do
     [ "$pid" = "1" ] && continue
     uid=$(awk "/^Uid:/{print \$2}" /proc/$pid/status 2>/dev/null)
     if [ "$uid" = "1000" ]; then
       echo "$pid"
       break
     fi
   done
   '
   ```

5. **Test 3 -- seccomp-BPF filter active on child** (VERT-03):
   Use `kubectl exec` with the child PID finder to read `/proc/<child>/status` for `Seccomp:` and `NoNewPrivs:` fields. Pass if `Seccomp: 2` AND `NoNewPrivs: 1`. Fail if either is missing or has wrong value.

6. **Test 4 -- Landlock LSM available on node** (VERT-03):
   Check `docker exec ${CLUSTER_NAME}-control-plane cat /sys/kernel/security/lsm` for `landlock`. If present, pass. If absent AND host is macOS (`uname -s` == `Darwin`), pass with info "expected on macOS, requires Linux 5.13+". If absent on Linux, fail. Follow the exact `make doctor` logic (Makefile lines 204-213).

7. **Test 5 -- Network namespace isolation** (VERT-03):
   Use `kubectl exec` to read `/proc/<child_pid>/net/dev` and compare against `/proc/1/net/dev`. If they differ (child has a different set of interfaces), network namespace isolation is confirmed. Alternatively, check for `10.200.0` or `veth` in the child's net/dev output. Pass if child network namespace is isolated, fail if same as supervisor.

8. **Test 6 -- Supervisor logs show policy/startup evidence** (VERT-02):
   `kubectl logs -n openshell openclaw-sandbox --tail=200` piped through `grep -ci` for patterns like `policy|config|sandbox|spawn|child|proxy|started`. Pass if at least one match found. Fail if zero matches. Use case-insensitive grep. Log a warning on failure that exact supervisor log format is unknown.

9. **Summary**: Print "Results: N passed, M failed", exit with FAILED count.

**Important design decisions:**
- Do NOT use `pgrep` or `ps` (may not be in the container image). Use `/proc` filesystem directly.
- Do NOT hard-fail on registration Job absence -- warn and continue (allows partial verification).
- macOS Landlock absence is NOT a failure (match `make doctor` behavior exactly).
- Use `sh -c` for kubectl exec (not bash -- container may only have sh).
- All kubectl exec uses the pod name `openclaw-sandbox` directly (StatefulSet, predictable name).
