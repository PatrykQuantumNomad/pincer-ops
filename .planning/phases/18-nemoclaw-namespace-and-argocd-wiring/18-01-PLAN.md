Create the directory infrastructure/nemoclaw/base/ and three files:

1. **namespace.yaml** -- Explicit namespace manifest with all six PSS labels. Must include:
   - `apiVersion: v1`, `kind: Namespace`, `metadata.name: nemoclaw`
   - All six PSS labels per user decision:
     - `pod-security.kubernetes.io/enforce: restricted`
     - `pod-security.kubernetes.io/enforce-version: latest`
     - `pod-security.kubernetes.io/audit: restricted`
     - `pod-security.kubernetes.io/audit-version: latest`
     - `pod-security.kubernetes.io/warn: restricted`
     - `pod-security.kubernetes.io/warn-version: latest`
   - Include a header comment explaining PSS enforcement purpose and that LiteLLM workloads (Phase 19) must comply with restricted PSS
   - Do NOT use CreateNamespace=true -- this manifest IS the namespace creation mechanism (per user decision)

2. **networkpolicy.yaml** -- Default-deny NetworkPolicy. Must include:
   - `apiVersion: networking.k8s.io/v1`, `kind: NetworkPolicy`
   - `metadata.name: default-deny-all`, `metadata.namespace: nemoclaw`
   - `spec.podSelector: {}` (empty -- selects all pods)
   - `spec.policyTypes` with both `Ingress` and `Egress`
   - Include a header comment noting Phase 19 adds specific allow rules on top of this deny-all baseline
   - Do NOT include any allow rules -- only deny-all. This matches the openclaw pattern but without the second NetworkPolicy resource (allow rules come in Phase 19)

3. **kustomization.yaml** -- Base kustomization listing resources. Must include:
   - `apiVersion: kustomize.config.k8s.io/v1beta1`, `kind: Kustomization`
   - `namespace: nemoclaw` (matches openclaw base pattern)
   - `resources:` listing `namespace.yaml` first, then `networkpolicy.yaml` (namespace before namespace-scoped resources)
  </action>

  </verify>
  <done>

    - kustomization.yaml references both resources with namespace: nemoclaw
    - `kubectl kustomize infrastructure/nemoclaw/base` renders 2 resources (Namespace + NetworkPolicy)
  </done>
