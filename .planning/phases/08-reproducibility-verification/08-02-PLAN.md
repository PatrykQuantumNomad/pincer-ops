<task type="auto">
  <name>Task 1: Teardown and rebuild the cluster</name>
  <files></files>
  <action>
    Run the complete teardown/rebuild cycle. This modifies no files -- it exercises the existing scripts against the real repoURL.

    IMPORTANT PRE-CHECK: Before teardown, verify the sealing key backup exists:
    `ls -la ~/.pincer/sealed-secrets-key.yaml`
    If the backup does NOT exist, abort and inform the user -- teardown without a key backup means SealedSecrets will be permanently lost.

    1. **Verify repoURL changes are on remote:**
       `git log origin/main --oneline -3` -- should show the repoURL fix commit from Plan 01.
       If NOT present, abort -- ArgoCD will fail to sync.

    2. **Run teardown (without --clean flag):**
       `./scripts/teardown.sh`
       This destroys the KIND cluster but preserves:
       - ~/.pincer/sealed-secrets-key.yaml (sealing key backup)
       - KIND Docker network (may or may not survive)

    3. **Run bootstrap:**
       `./scripts/bootstrap.sh`
       This recreates the entire cluster. With the real repoURL, ArgoCD should sync all Applications from Git rather than triggering the kustomize fallback paths.

       Expected duration: 3-8 minutes (cluster creation + ArgoCD install + sync waves).

       MONITOR for fallback warnings: If you see "ArgoCD cannot sync from repo (repo unreachable?)" warnings, note them but let bootstrap complete -- the fallback will still produce a working cluster, but this would indicate the GitOps sync path is not working as expected.

    4. **Wait for ArgoCD to stabilize (post-bootstrap):**
       After bootstrap.sh completes, ArgoCD may still be processing sync waves. Wait up to 120 seconds for all Applications to settle:
       ```
       for i in $(seq 1 24); do
         HEALTH=$(kubectl get applications -n argocd -o jsonpath='{range .items[*]}{.metadata.name}={.status.health.status}{" "}{end}' 2>/dev/null)
         echo "Check $i: $HEALTH"
         if echo "$HEALTH" | grep -qv "Progressing"; then
           break
         fi
         sleep 5
       done
       ```
  </action>
  <verify>
    1. `kind get clusters` includes `openclaw-dev`
    2. `kubectl get nodes` shows 3 Ready nodes
    3. `kubectl get pods -n argocd` shows ArgoCD pods running
    4. bootstrap.sh exited with code 0
  </verify>
  <done>Cluster has been torn down and rebuilt successfully. bootstrap.sh completed without errors. ArgoCD and all infrastructure components are running.</done>
</task>

<task type="auto">
  <name>Task 2: Verify ArgoCD Applications, OpenClaw health, and SealedSecrets persistence</name>
  <files></files>
  <action>
    Run the full verification checklist. This task reads cluster state -- no file modifications.

    **CHECK 1: All ArgoCD Applications are Healthy/Synced**
    ```
    kubectl get applications -n argocd
    ```
    Expected: ALL applications show Synced and Healthy (or Progressing briefly).
    Applications to verify: root, argocd-self, infra-metallb, infra-envoy-gateway, infra-envoy-gateway-config, infra-sealed-secrets, infra-cert-manager, workload-openclaw.

    If any Application shows ComparisonError, the repoURL fix did not take effect -- check git log origin/main.
    If any Application shows OutOfSync, wait 60s and re-check (sync waves may still be processing).
    If any Application shows Degraded or Missing, investigate with: `kubectl get app <name> -n argocd -o yaml`

    Note: infra-envoy-gateway uses OCI Helm (not Git), so its sync status is independent of the repoURL fix.

    **CHECK 2: ArgoCD synced from Git (not fallback)**
    Check bootstrap.sh output (from Task 1) for absence of fallback warnings ("repo unreachable"). If fallback warnings appeared, record which components used fallback vs Git sync.

    **CHECK 3: OpenClaw health check**
    ```
    # Via localhost (through Envoy Gateway)
    curl -s -o /dev/null -w "%{http_code}" http://localhost/health
    ```
    Expected: 200 (or a successful response). If OpenClaw uses exec-based probes and /health is not exposed via HTTP, use:
    ```
    kubectl exec -n openclaw statefulset/openclaw-gateway -- node -e "fetch('http://localhost:18789/health').then(r => console.log(r.status))"
    ```
    Or check pod status:
    ```
    kubectl get pods -n openclaw
    kubectl get statefulset openclaw-gateway -n openclaw
    ```
    Pod should be Running with 1/1 Ready.

    **CHECK 4: SealedSecrets decryption after rebuild**
    ```
    kubectl get secret openclaw-credentials -n openclaw -o jsonpath='{.data.OPENCLAW_GATEWAY_TOKEN}' | base64 -d | head -c 5
    ```
    Expected: Non-empty output (first 5 chars of the decrypted token). If empty, the sealing key was not properly restored and SealedSecrets are broken.

    Also verify the sealing key backup was refreshed:
    ```
    ls -la ~/.pincer/sealed-secrets-key.yaml
    ```
    File should have a recent timestamp (from this bootstrap run).

    **CHECK 5: No manual intervention was needed**
    Confirm that between running teardown.sh and the verification checks above, NO manual kubectl apply/create/patch commands were run. The only commands should have been:
    - ./scripts/teardown.sh
    - ./scripts/bootstrap.sh
    - Verification read-only commands (get, describe, exec, curl)

    **RECORD RESULTS:**
    Create a structured summary of all 5 checks with PASS/FAIL status for the checkpoint task.
  </action>
  <verify>
    1. All ArgoCD Applications show Healthy status: `kubectl get applications -n argocd -o jsonpath='{range .items[*]}{.metadata.name}: {.status.health.status}{"\n"}{end}'`
    2. OpenClaw pod is Running 1/1: `kubectl get pods -n openclaw -l app=openclaw-gateway`
    3. SealedSecret decrypted successfully: `kubectl get secret openclaw-credentials -n openclaw -o jsonpath='{.data.OPENCLAW_GATEWAY_TOKEN}'` returns non-empty base64 string
  </verify>
  <done>All 5 verification checks pass: ArgoCD Applications Healthy/Synced, OpenClaw accessible, SealedSecrets decryptable, no manual intervention needed, ArgoCD synced from Git.</done>
</task>
