**Step 3: Verify all components**

1. `kubectl get pods -n envoy-gateway-system` -- controller pod Running, envoy proxy DaemonSet pod Running on CP node
2. `kubectl get gatewayclass eg` -- should show ACCEPTED
3. `kubectl get gateway eg -n envoy-gateway-system` -- should show Programmed with listeners
4. `kubectl get app infra-envoy-gateway -n argocd` -- should show Healthy/Synced (or at least present if placeholder repoURL blocks root-app discovery)
5. `kubectl get app infra-envoy-gateway-config -n argocd` -- should show present (may have ComparisonError due to placeholder repoURL, but resources are applied directly)

**Step 4: Verify hostPort binding**
```bash
kubectl get pods -n envoy-gateway-system -o wide
```
The Envoy proxy pod should be running on the control-plane node (the one with `ingress-ready=true` label). Check the pod spec to confirm hostPort 80 and 443 are bound:
```bash
kubectl get pod -n envoy-gateway-system -l gateway.envoyproxy.io/owning-gateway-name=eg -o jsonpath='{.items[0].spec.containers[0].ports}'
```
(Adjust label selector if needed based on actual DaemonSet labels)

**Step 5: Test HTTP routing**
Deploy a test backend and HTTPRoute:
```bash
# Create test namespace and backend
kubectl create deployment test-backend --image=hashicorp/http-echo --port=5678 -- -text="gateway-api-ok"
kubectl expose deployment test-backend --port=80 --target-port=5678

# Create HTTPRoute
kubectl apply -f - <<EOF
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: test-route
  namespace: default
spec:
  parentRefs:
    - name: eg
      namespace: envoy-gateway-system
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /test
      backendRefs:
        - name: test-backend
          port: 80
EOF

# Wait for route to be accepted
sleep 10

# Test from host
curl -s http://localhost:80/test
```
Expected output should contain "gateway-api-ok" (or the echo response).

If `curl localhost:80/test` fails:
- Check if the Envoy proxy pod is actually bound to hostPort: `kubectl describe pod -n envoy-gateway-system -l gateway.envoyproxy.io/owning-gateway-name=eg | grep -A5 "Ports"`
- Check if the containerPort mapping is correct (8080->80, 8443->443): `kubectl get pod -n envoy-gateway-system -o yaml | grep -A3 hostPort`
- Check Gateway status: `kubectl get gateway eg -n envoy-gateway-system -o yaml | grep -A20 status`
- If containerPort values are wrong, update envoy-proxy-config.yaml and re-apply

**Step 6: Clean up test resources**
```bash
kubectl delete httproute test-route
kubectl delete service test-backend
kubectl delete deployment test-backend
```

**Runtime fixes:** If any bootstrap.sh step fails during execution, fix the script and re-run. Document all deviations in the summary. The research flagged these as MEDIUM confidence items needing runtime validation:
