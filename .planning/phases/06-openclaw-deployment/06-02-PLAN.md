**Step 16: Deploy OpenClaw**

Insert after Step 15 (cert-manager) and before the Done banner.

Pattern: Apply ArgoCD Application directly, poll for StatefulSet creation, kustomize direct-apply fallback on ComparisonError timeout, then wait for rollout.

```bash
# Step 16: Deploy OpenClaw
OC_OVERLAY_DIR="${SCRIPT_DIR}/../workloads/openclaw/overlays/dev"
log_step "Deploying OpenClaw..."

# Apply the workload-openclaw Application directly
run_cmd kubectl apply -f "${BOOTSTRAP_DIR}/workload-openclaw.yaml"

# Wait for StatefulSet to be created (ArgoCD sync or fallback)
OC_WAIT=0
OC_TIMEOUT=180
until kubectl get statefulset openclaw-gateway -n openclaw >/dev/null 2>&1; do
  if [ ${OC_WAIT} -ge ${OC_TIMEOUT} ]; then
    ROOT_STATUS=$(kubectl get app root -n argocd -o jsonpath='{.status.conditions[0].type}' 2>/dev/null || echo "")
    if [ "${ROOT_STATUS}" = "ComparisonError" ]; then
      log_warn "ArgoCD cannot sync from repo -- applying OpenClaw directly"
      run_cmd kubectl create namespace openclaw --dry-run=client -o yaml | kubectl apply -f -
      run_cmd kubectl apply --server-side --force-conflicts -f <(kubectl kustomize "${OC_OVERLAY_DIR}")
      break
    fi
    log_error "Timed out waiting for OpenClaw StatefulSet (${OC_TIMEOUT}s)"
    exit 1
  fi
  sleep 5
  OC_WAIT=$((OC_WAIT + 5))
done
run_cmd kubectl rollout status statefulset/openclaw-gateway -n openclaw --timeout=300s
log_info "OpenClaw gateway is running"
```

Key details:
- Use `OC_OVERLAY_DIR` pointing to `workloads/openclaw/overlays/dev` (same path the ArgoCD Application targets)
- The namespace creation uses the `--dry-run=client -o yaml | kubectl apply` pipe pattern (established in Steps 6 and 11)
- StatefulSet rollout timeout is 300s (5 min) because the image may need to pull from ghcr.io on first run
- The kustomize fallback creates the namespace first (CreateNamespace=true only works via ArgoCD sync)

- Re-apply the manifests
- Verify the Secret is created in the openclaw namespace

**Handle health probe issues:** If the pod enters CrashLoopBackOff due to probe failures:
- Check pod logs: `kubectl logs statefulset/openclaw-gateway -n openclaw`

- If OpenClaw exposes an unauthenticated HTTP /health endpoint, consider switching from exec to httpGet probe (simpler, lower overhead)
