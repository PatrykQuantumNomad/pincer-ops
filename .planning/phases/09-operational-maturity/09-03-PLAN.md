Create `workloads/openclaw/base/backup-rbac.yaml`:
- A ServiceAccount named `openclaw-backup` in namespace `openclaw`
- This ServiceAccount exists so the CronJob runs with a dedicated identity (principle of least privilege). The backup CronJob only needs filesystem access, not API access, but a dedicated SA is still best practice.

Create `workloads/openclaw/base/backup-cronjob.yaml`:
- apiVersion: batch/v1, kind: CronJob
- name: `openclaw-backup`, namespace: `openclaw`
- schedule: `"0 2 * * *"` (daily at 2 AM)
- concurrencyPolicy: Forbid (never overlap backup runs)
- successfulJobsHistoryLimit: 3, failedJobsHistoryLimit: 3
- jobTemplate.spec.template.spec:
  - serviceAccountName: `openclaw-backup`
  - **podAffinity** (CRITICAL for RWO PVC):
    ```yaml
    affinity:
      podAffinity:
        requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchLabels:
                app.kubernetes.io/name: openclaw-gateway
            topologyKey: kubernetes.io/hostname
    ```
    This ensures the backup pod lands on the same node as the StatefulSet pod, which is REQUIRED because the PVC `data-openclaw-gateway-0` uses ReadWriteOnce access mode.
  - Container:
    - name: backup
    - image: `busybox:1.37` (lightweight, has tar)
    - imagePullPolicy: IfNotPresent (KIND requirement)
    - command: shell script that:
      1. Creates timestamped backup: `tar czf /backups/openclaw-$(date +%Y%m%d-%H%M%S).tar.gz -C /data .`
      2. Retains only last 7 backups: `ls -t /backups/openclaw-*.tar.gz | tail -n +8 | xargs rm -f`
      3. Prints success message
    - volumeMounts:
      - `/data` (PVC, readOnly: true)
      - `/backups` (hostPath for backup storage)
    - resources: requests 64Mi/100m, limits 256Mi/500m
  - restartPolicy: OnFailure
  - volumes:
    - name: data, persistentVolumeClaim: claimName: `data-openclaw-gateway-0`, readOnly: true
    - name: backups, hostPath: path: `/tmp/openclaw-backups`, type: DirectoryOrCreate

Add comment header explaining: RWO PVC constraint requires podAffinity, backups are ephemeral on KIND (lost on teardown -- acceptable for dev), busybox chosen for minimal image footprint.

   - resources: ["secrets"]
   - verbs: ["get", "list"]
3. RoleBinding named `sealed-secrets-key-backup` in namespace `kube-system`:
   - subjects: ServiceAccount `sealed-secrets-key-backup` in kube-system
   - roleRef: Role `sealed-secrets-key-reader`

Create `infrastructure/sealed-secrets/base/backup-cronjob.yaml`:
- apiVersion: batch/v1, kind: CronJob
- name: `sealed-secrets-key-backup`, namespace: `kube-system`
- schedule: `"0 3 * * *"` (daily at 3 AM, offset from PVC backup)
- concurrencyPolicy: Forbid
- successfulJobsHistoryLimit: 3, failedJobsHistoryLimit: 3
- jobTemplate.spec.template.spec:
  - serviceAccountName: `sealed-secrets-key-backup`
  - Container:
    - name: backup
    - image: `bitnami/kubectl:1.32` (provides kubectl CLI)
    - imagePullPolicy: IfNotPresent (KIND requirement)
    - command: shell script that:
      1. Exports sealing keys: `kubectl get secret -n kube-system -l sealedsecrets.bitnami.com/sealed-secrets-key -o yaml > /backups/sealed-secrets-key-$(date +%Y%m%d-%H%M%S).yaml`
      2. Retains only last 7 backups: `ls -t /backups/sealed-secrets-key-*.yaml | tail -n +8 | xargs rm -f`
      3. Prints success message
    - volumeMounts:
      - `/backups` (hostPath)
    - resources: requests 32Mi/50m, limits 64Mi/100m
  - restartPolicy: OnFailure
  - volumes:
    - name: backups, hostPath: path: `/tmp/sealed-secrets-backups`, type: DirectoryOrCreate
