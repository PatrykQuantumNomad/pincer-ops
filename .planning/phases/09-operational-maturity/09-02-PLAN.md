  <name>Task 1: Create ArgoCD notifications ConfigMap with triggers, templates, and webhook service</name>
  <files>
    bootstrap/argocd-notifications-cm.yaml
  </files>
  <action>
Create `bootstrap/argocd-notifications-cm.yaml` -- a ConfigMap in the argocd namespace named `argocd-notifications-cm`.

This is a SEPARATE resource from `argocd-cm.yaml` (which handles core ArgoCD config). Do NOT merge them.

Content in the `data:` section:

1. **Webhook service definition** -- `service.webhook.platform-webhook`:
   - URL: `http://localhost:9999/webhook` (placeholder -- local dev cluster has no external endpoint. This URL is configurable; the important thing is the notification infrastructure is in place.)
   - Headers: Content-Type: application/json

2. **Triggers**:
   - `trigger.on-sync-failed`: fires when `app.status.operationState.phase in ['Error', 'Failed']`, sends `[app-sync-failed]`
   - `trigger.on-health-degraded`: fires when `app.status.health.status == 'Degraded'`, sends `[app-health-degraded]`
   - `trigger.on-sync-status-unknown`: fires when `app.status.sync.status == 'Unknown'`, sends `[app-sync-status-unknown]`

3. **Templates**:
   - `template.app-sync-failed`: POST webhook with JSON body containing event, app name, message, timestamp
   - `template.app-health-degraded`: POST webhook with JSON body containing event, app name, health status, message
   - `template.app-sync-status-unknown`: POST webhook with JSON body containing event, app name

Add a comment header explaining this is the ArgoCD Notifications ConfigMap (not argocd-cm) and that the webhook URL is a placeholder for local dev.

Include standard labels: `app.kubernetes.io/name: argocd-notifications-cm`, `app.kubernetes.io/part-of: argocd`.

This file lives in bootstrap/ so root-app discovers it via directory scan. It does NOT need a sync-wave annotation (it's a ConfigMap, not an Application).
  </action>
  <verify>
Run `kubectl apply --dry-run=client -f bootstrap/argocd-notifications-cm.yaml` to validate the manifest structure. Verify the YAML is valid and contains all three triggers and three templates. Confirm the ConfigMap name is `argocd-notifications-cm` (not `argocd-cm`).
  </verify>
  <done>

  </done>

Add notification subscription annotations to the `metadata.annotations` section of each ArgoCD Application manifest listed above. Add these three annotations to EACH file:

```yaml

notifications.argoproj.io/subscribe.on-health-degraded.platform-webhook: ""
notifications.argoproj.io/subscribe.on-sync-status-unknown.platform-webhook: ""
```

These annotations tell ArgoCD's notification controller to evaluate the named triggers for each Application and send notifications via the `platform-webhook` service when conditions match.

Do NOT add annotations to `root-app.yaml` -- the root app is a special case that manages all other apps. Its sync status is always unusual due to the self-referential nature of App of Apps.

Read each file first to understand the existing annotation structure before modifying.
