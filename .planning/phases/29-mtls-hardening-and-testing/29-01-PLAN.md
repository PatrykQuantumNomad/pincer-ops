       **Resolved: Why openshell-client-tls (not openshell-server-client-ca) for tls-client-ca volume.**
       The upstream Helm chart defaults to a separate `openshell-server-client-ca` secret, but the gateway binary does NOT look up secrets by name -- it reads the CA cert file from the path specified by `OPENSHELL_TLS_CLIENT_CA` (i.e., `/etc/openshell-tls/client-ca/ca.crt`). The volume mount determines which secret provides that file. cert-manager Certificate secrets always include a `ca.crt` key containing the CA that signed the certificate. Since the client cert (`openshell-client-tls`) was signed by our `openshell-ca-issuer`, its `ca.crt` field IS the root CA cert needed to verify client connections. Mounting `openshell-client-tls`'s `ca.crt` via the `items` selector is equivalent to what the Helm chart achieves with a separate secret, while avoiding the need to create or sync an additional Secret resource.

       - UPDATE the header comment: remove "TLS is disabled via OPENSHELL_DISABLE_TLS for dev; Phase 29 enables mTLS." and replace with "mTLS enabled: server cert from openshell-server-tls, client CA from openshell-client-tls."

         generate_tls_artifacts() {
           log_step "Generating TLS artifacts for OpenShell mTLS..."

           local TLS_DIR="${SCRIPT_DIR}/../infrastructure/openshell/gateway"

           # Apply root CA Certificate (issued by selfsigned-issuer)
           run_cmd kubectl apply -f "${TLS_DIR}/certificate-ca.yaml"

           # Wait for CA certificate to be issued before creating the ClusterIssuer
           run_cmd kubectl wait --for=condition=Ready certificate/openshell-ca \
             -n cert-manager --timeout=120s

           # Apply CA ClusterIssuer (needs CA secret to exist)
           run_cmd kubectl apply -f "${TLS_DIR}/clusterissuer-ca.yaml"

           # Apply server and client certificates
           run_cmd kubectl apply -f "${TLS_DIR}/certificate-server.yaml"
           run_cmd kubectl apply -f "${TLS_DIR}/certificate-client.yaml"

           # Wait for both certificates to be issued
           run_cmd kubectl wait --for=condition=Ready certificate/openshell-server-tls \
             -n openshell --timeout=120s
           run_cmd kubectl wait --for=condition=Ready certificate/openshell-client-tls \

           log_info "TLS artifacts generated -- mTLS certificates issued by cert-manager"
         }

The bootstrap script runs generate_tls_artifacts() after cert-manager is ready on both providers.
