  <action>
    1. **Generate the Sandbox CRD JSON schema:**
       - Download the agent-sandbox CRD manifest from the upstream repository (the same URL used in infrastructure/agent-sandbox/base/kustomization.yaml).
       - Extract the OpenAPI v3 schema from the CRD's `spec.versions[0].schema.openAPIV3Schema` field.
       - Convert it to a standalone JSON schema file compatible with kubeconform. The JSON schema must include:
         - `"$schema": "http://json-schema.org/draft-07/schema#"` (or draft-04 which kubeconform also supports)
         - The `properties` from the CRD's openAPIV3Schema (apiVersion, kind, metadata, spec, status)
         - `"x-kubernetes-group-version-kind"` array with `[{"group": "agents.x-k8s.io", "kind": "Sandbox", "version": "v1alpha1"}]`
       - If the CRD download is complex or the openAPIV3Schema extraction is fragile, the alternative approach is to manually craft a minimal JSON schema that validates the key Sandbox CR fields used in our manifests: `spec.podTemplate` (object), `spec.volumeClaimTemplates` (array). A minimal schema that allows kubeconform to recognize and not skip Sandbox resources is sufficient.
       - Create the directory `schemas/agents.x-k8s.io/` and save the schema as `sandbox_v1alpha1.json`.
       - IMPORTANT: The filename must be lowercase `sandbox` (not `Sandbox`) -- kubeconform's `{{.ResourceKind}}` template produces lowercase Kind names.

    2. **Update validate-manifests.sh** (TEST-02):
       - Add a `SCHEMA_LOCATION_LOCAL` constant after the existing `SCHEMA_LOCATION` constant:
         ```bash
         readonly SCHEMA_LOCATION_LOCAL="${SCRIPT_DIR}/../schemas/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json"
         ```
       - Update `KUBECONFORM_FLAGS` to include the local schema location:
         ```bash
         readonly KUBECONFORM_FLAGS="-summary -output text -kubernetes-version ${K8S_VERSION} -schema-location default -schema-location ${SCHEMA_LOCATION} -schema-location ${SCHEMA_LOCATION_LOCAL}"
         ```
       - The local schema takes lowest priority (last `-schema-location`). kubeconform checks `default` first, then CRDs-catalog, then local. This ensures standard K8s resources and known CRDs still use their upstream schemas, and only unknown CRDs (like Sandbox) fall back to local.
       - Update the "Skipped infrastructure bases" echo section to note that agent-sandbox CRD validation is now handled via local schema (not skipped).

    3. **Verify the schema works** by running kubeconform manually:
       ```bash
       kubectl kustomize workloads/openclaw-sandbox/overlays/dev | kubeconform -summary -output text -kubernetes-version 1.32.0 -schema-location default -schema-location "schemas/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json"
       ```
       This should validate the Sandbox CR without "could not find schema" warnings.
  </action>
