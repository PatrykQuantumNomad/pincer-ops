<objective>
Create and enforce NetworkPolicy resources that lock down the openclaw namespace to default-deny for both ingress and egress, with explicit allow rules for DNS resolution, HTTPS egress to LLM APIs, and ingress from the Envoy Gateway proxy.

Purpose: Enforce least-privilege network access for OpenClaw. Without NetworkPolicy, any pod in the cluster can reach OpenClaw and OpenClaw can reach any destination. This phase restricts traffic to only what is operationally required.
Output: Two NetworkPolicy resources (default-deny-all + openclaw-allow) deployed to the openclaw namespace and verified against the running workload.
</objective>

<task type="auto">
  <name>Task 1: Create NetworkPolicy manifests and update kustomization</name>
  <files>workloads/openclaw/base/networkpolicy.yaml, workloads/openclaw/base/kustomization.yaml</files>
  <action>
Create `workloads/openclaw/base/networkpolicy.yaml` containing TWO NetworkPolicy resources separated by `---`:

**Resource 1: default-deny-all**
- apiVersion: networking.k8s.io/v1, kind: NetworkPolicy
- metadata.name: default-deny-all, metadata.namespace: openclaw
- spec.podSelector: {} (selects all pods in namespace)
- spec.policyTypes: [Ingress, Egress]
- NO ingress or egress rules (empty spec = deny all)

**Resource 2: openclaw-allow**
- apiVersion: networking.k8s.io/v1, kind: NetworkPolicy
- metadata.name: openclaw-allow, metadata.namespace: openclaw
- spec.podSelector.matchLabels: app.kubernetes.io/name: openclaw-gateway (must match the label on the StatefulSet pod template)
- spec.policyTypes: [Ingress, Egress]
- Ingress rule: Allow from namespaceSelector `kubernetes.io/metadata.name: envoy-gateway-system` on TCP port 18789
- Egress rule 1 (DNS): Allow to namespaceSelector `kubernetes.io/metadata.name: kube-system` on UDP 53 and TCP 53
- Egress rule 2 (HTTPS): Allow to ipBlock cidr `0.0.0.0/0` on TCP 443

Add a file header comment explaining the two-resource pattern and the CRITICAL note that both must be deployed together.

Update `workloads/openclaw/base/kustomization.yaml` to add `networkpolicy.yaml` to the resources list (add it as the last entry, after httproute.yaml).

Validate the manifests build correctly:
```
kustomize build workloads/openclaw/overlays/dev/
```
This must succeed without errors and the output must contain both NetworkPolicy resources.
  </action>
  <verify>
Run `kustomize build workloads/openclaw/overlays/dev/` and confirm:
1. Output contains `kind: NetworkPolicy` with `name: default-deny-all`
2. Output contains `kind: NetworkPolicy` with `name: openclaw-allow`
3. The openclaw-allow policy has ingress from envoy-gateway-system on port 18789
4. The openclaw-allow policy has egress to kube-system on port 53 (UDP+TCP)
5. The openclaw-allow policy has egress to 0.0.0.0/0 on port 443
6. No kustomize build errors
  </verify>
  <done>
networkpolicy.yaml exists with two valid NetworkPolicy resources (default-deny-all + openclaw-allow). kustomization.yaml includes networkpolicy.yaml. `kustomize build` succeeds and produces correct output.
  </done>

<task type="auto">
  <name>Task 2: Apply NetworkPolicy and verify OpenClaw connectivity</name>
  <files>workloads/openclaw/base/networkpolicy.yaml</files>
  <action>
Apply the NetworkPolicy manifests to the running cluster and verify OpenClaw remains fully functional.

**Step 1: Verify cluster is running and OpenClaw is healthy BEFORE applying policies**
```
kubectl get statefulset -n openclaw openclaw-gateway
curl -s -o /dev/null -w "%{http_code}" localhost/health
```
Both must succeed. If the cluster is not running, run `./scripts/bootstrap.sh` first.

**Step 2: Apply the NetworkPolicy via kustomize**
```
kubectl apply -k workloads/openclaw/base/
```
This applies all resources including the new NetworkPolicy. Both deny-all and allow policies are applied atomically.

**Step 3: Verify NetworkPolicy resources exist**
```
kubectl get networkpolicy -n openclaw
```
Must show both `default-deny-all` and `openclaw-allow`.

**Step 4: Verify DNS egress works (CRITICAL -- most common failure mode)**
```
kubectl exec -n openclaw statefulset/openclaw-gateway -- \
  node -e "require('dns').resolve('api.anthropic.com', (err, addr) => { if(err) { console.error(err); process.exit(1) } else { console.log('DNS OK:', addr) } })"
```
Must resolve successfully (prints IP addresses).

**Step 5: Verify HTTPS egress works**
```
kubectl exec -n openclaw statefulset/openclaw-gateway -- \
  node -e "const https = require('https'); const req = https.get('https://api.anthropic.com', r => { console.log('HTTPS OK:', r.statusCode); process.exit(0) }); req.on('error', e => { console.error(e); process.exit(1) }); req.setTimeout(10000, () => { console.error('Timeout'); process.exit(1) })"
```
Must connect and return a status code (likely 401 without auth, which is fine -- the connection succeeded).

**Step 6: Verify ingress from Envoy Gateway works**
```
curl -s -o /dev/null -w "%{http_code}" localhost/health
```
Must return a success status code (200 or similar). This proves ingress from the Envoy Gateway proxy through the NetworkPolicy to OpenClaw on port 18789.

**Step 7: Verify blocked traffic is actually blocked**
Test that non-443 TCP egress is denied:
```
kubectl exec -n openclaw statefulset/openclaw-gateway -- \
  node -e "const http = require('http'); const req = http.get('http://example.com:80', r => { console.log('UNEXPECTED:', r.statusCode); process.exit(1) }); req.on('error', e => { console.log('Blocked OK:', e.code) }); req.setTimeout(5000, () => { console.log('Blocked OK: timeout'); req.destroy(); process.exit(0) })"
```
Must timeout or error (connection refused/ETIMEDOUT), confirming port 80 egress is blocked.

**Step 8: Verify ArgoCD Application sync status**
```
kubectl get app workload-openclaw -n argocd -o jsonpath='{.status.sync.status}'
```
Should show Synced or OutOfSync (OutOfSync is expected if ArgoCD hasn't picked up the new manifests yet -- the policies are already applied via kubectl). This is informational only.

If any verification step fails, check:
- DNS failure: Verify kube-system namespace has the `kubernetes.io/metadata.name` label (`kubectl get ns kube-system --show-labels`)
- HTTPS failure: Verify the egress rule has `cidr: 0.0.0.0/0` and `port: 443`
- Ingress failure: Verify the ingress rule namespaceSelector matches `envoy-gateway-system` and port is 18789
  </action>
  <verify>
All 5 connectivity checks pass:
1. `kubectl get networkpolicy -n openclaw` shows both policies
2. DNS resolution succeeds from inside the pod
3. HTTPS connection to api.anthropic.com succeeds from inside the pod
4. `curl localhost/health` returns success from outside the cluster
5. HTTP port 80 egress is blocked (timeout or connection refused)
  </verify>
  <done>
NetworkPolicy is enforced on the openclaw namespace. Default-deny blocks all unspecified traffic. OpenClaw remains fully functional: DNS works, LLM API egress works, health endpoint is reachable via localhost. Non-allowed traffic is confirmed blocked.
  </done>
