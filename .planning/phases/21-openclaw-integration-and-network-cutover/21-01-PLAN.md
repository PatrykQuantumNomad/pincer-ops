<objective>
Route OpenClaw inference through the LiteLLM governance proxy and restrict direct LLM API access.

Purpose: This is the integration cutover that connects OpenClaw to the NemoClaw governance layer. After this plan, OpenClaw routes all model requests through the LiteLLM proxy (which holds the API keys) rather than calling LLM APIs directly. This enforces credential isolation and centralizes inference governance.

Output: Updated configmap.yaml with models.providers.litellm section, updated networkpolicy.yaml with cross-namespace egress to LiteLLM proxy on port 4000 and clarified HTTPS egress comment.
</objective>

  <name>Task 2: Add cross-namespace LiteLLM egress and update HTTPS egress comment</name>
  <files>workloads/openclaw/base/networkpolicy.yaml</files>
  <action>
Update workloads/openclaw/base/networkpolicy.yaml to add a new egress rule allowing OpenClaw to reach the LiteLLM proxy in the nemoclaw namespace, and update the existing HTTPS egress comment to clarify the credential isolation enforcement model.

Changes to the `openclaw-allow` NetworkPolicy egress section:

1. **Add new egress rule** (insert BETWEEN the DNS rule and the HTTPS rule):
```yaml
    # Allow egress to LiteLLM governance proxy in nemoclaw namespace
    - to:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: nemoclaw
          podSelector:
            matchLabels:
              app.kubernetes.io/name: litellm-proxy
      ports:
        - protocol: TCP
          port: 4000
```

CRITICAL: The `namespaceSelector` and `podSelector` MUST be siblings under the SAME `to` list item (same `-` prefix) to create an AND condition. If they are separate `to` entries (separate `-` prefix), it becomes an OR condition and allows traffic to ALL pods in nemoclaw namespace.

2. **Update the HTTPS egress comment** (replace the existing comment above the 443 rule):
```yaml
    # Allow HTTPS egress for messaging platforms (Telegram, Discord, Slack,
    # WhatsApp, etc.) and web browsing tools. Note: standard NetworkPolicy
    # cannot filter by FQDN, so this allows all HTTPS egress. Direct LLM API
    # access is prevented by credential isolation (no API keys in OpenClaw
    # pod), not by network filtering.
```

3. **Update the file header comment** to reflect the new rule set:
```
# networkpolicy.yaml -- Default-deny + selective allow for openclaw namespace.
#
# Two NetworkPolicy resources:
#   1. default-deny-all: Blocks all ingress and egress for every pod in the namespace.
#   2. openclaw-allow: Permits DNS egress, LiteLLM proxy egress, HTTPS egress,
#      and ingress from Envoy Gateway.
#
# CRITICAL: Both resources must be deployed together. Deploying deny-all without
# allow rules will break OpenClaw connectivity immediately (no DNS, no API calls,
# no ingress from the gateway proxy).
```

Preserve:
- The `default-deny-all` NetworkPolicy unchanged
- The `podSelector` on openclaw-allow unchanged
- The ingress rule (Envoy Gateway) unchanged
- The DNS egress rule unchanged
- The HTTPS ipBlock egress rule unchanged (only the comment changes)
