  <name>Task 1: Create KIND config and shared script library</name>
  <files>cluster/kind-config.yaml, scripts/lib/common.sh</files>
  <action>
Create two files:

**cluster/kind-config.yaml** -- KIND cluster definition:
- API: `kind.x-k8s.io/v1alpha4`, kind: `Cluster`
- 3 nodes: 1 control-plane + 2 workers
- Control-plane node has `labels: { ingress-ready: "true" }` (use native `labels` field, NOT kubeadmConfigPatches)
- Control-plane has `extraPortMappings`: containerPort 80 -> hostPort 80 (TCP), containerPort 443 -> hostPort 443 (TCP)
- Worker nodes have no special config (bare `- role: worker`)

**scripts/lib/common.sh** -- Shared helper library (sourced by both bootstrap.sh and teardown.sh):

1. **Color/output setup:**
   - TTY detection: if stdout is a terminal (`[[ -t 1 ]]`) AND `NO_COLOR` env var is not set, define ANSI color variables (RED, GREEN, YELLOW, BLUE, BOLD, NC). Otherwise set all to empty strings.
   - Four log functions: `log_info` (green `[+]`), `log_warn` (yellow `[!]`, to stderr), `log_error` (red `[x]`, to stderr), `log_step` (blue `[>]` with bold text)

2. **Verbose mode:**
   - Global `VERBOSE=false` variable
   - `run_cmd()` function: if VERBOSE=true, run command with output visible; if false, redirect stdout+stderr to /dev/null. CRITICAL: the function must preserve the command's exit code.

3. **Argument parsing:**
   - `parse_args()` function that iterates over `$@` with a `case` statement
   - Supported flags: `--verbose` / `-v` (sets VERBOSE=true), `--clean` (sets CLEAN=true -- only meaningful for teardown but harmless to parse in bootstrap), `-h` / `--help` (calls `usage` function and exits 0), unknown options (log_error + exit 1)
   - CLEAN=false as default global

4. **Pre-flight checks:**
   - `check_port_free()` function: takes a port number, uses `lsof -i :PORT -sTCP:LISTEN -t` to detect listeners. If occupied, get process name via `ps -p PID -o comm=` and log_error with message like "Port 80 in use by httpd (PID: 1234). Free it and retry." Returns 1 if occupied, 0 if free.
   - `preflight_checks()` function: checks Docker daemon (`docker info`), KIND (`command -v kind`), kubectl (`command -v kubectl`). Only checks ports if Docker check passed (ports need network stack). Returns 1 if any check failed, 0 if all pass. Each failure gets a specific error message.

5. **Constants:**
   - `CLUSTER_NAME="openclaw-dev"`

All scripts must be bash 3.2 compatible (macOS default): no associative arrays, no mapfile, no `${var,,}`, no `|&`.
The file must start with a comment header but NOT a shebang (it is sourced, not executed directly).
  </action>

<task type="auto">
  <name>Task 2: Create idempotent bootstrap script</name>
  <files>scripts/bootstrap.sh</files>
  <action>
Create `scripts/bootstrap.sh` with `#!/usr/bin/env bash` shebang, `set -euo pipefail`, and executable permissions (`chmod +x`).

Source common.sh: `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` then `source "${SCRIPT_DIR}/lib/common.sh"`.

Define `KIND_CONFIG="${SCRIPT_DIR}/../cluster/kind-config.yaml"`.

Define a `usage()` function showing: "Usage: bootstrap.sh [--verbose|-v] [-h|--help]" with a brief description.

Main flow:
1. `parse_args "$@"`
2. `preflight_checks || exit 1`
3. Start elapsed timer: `SECONDS=0`
4. **Cluster creation (idempotent):** Check `kind get clusters 2>/dev/null | grep -q "^${CLUSTER_NAME}$"`. If exists: `log_info "Cluster '${CLUSTER_NAME}' already exists, skipping creation"`. If not: `log_step "Creating cluster..."`, run `kind create cluster --name "${CLUSTER_NAME}" --config "${KIND_CONFIG}" --wait 120s` via `run_cmd`. Log success.
5. **Wait for nodes:** `log_step "Waiting for nodes..."`, run `kubectl wait --for=condition=Ready nodes --all --timeout=120s` via `run_cmd`. Log success.
6. **CIDR detection (always runs):** `log_step "Detecting network CIDR..."`. Extract IPv4 subnet: `docker network inspect kind -f '{{range .IPAM.Config}}{{.Subnet}} {{end}}' | tr ' ' '\n' | grep -E '^[0-9]+\.'`. Validate result is not empty -- if empty, log_error "Failed to detect IPv4 subnet from KIND network" and exit 1. Log detected subnet.
7. **ConfigMap storage (always runs):** `log_step "Storing network info..."`. Use `kubectl create configmap kind-network-info --namespace kube-system --from-literal=ipv4-subnet="${KIND_SUBNET}" --dry-run=client -o yaml | kubectl apply -f -`. Log success.
8. Print elapsed time: `log_info "Bootstrap complete in ${SECONDS}s"`

IMPORTANT: When checking ports in preflight, the port check must be SKIPPED if the cluster already exists (the KIND cluster itself holds ports 80/443). Approach: In bootstrap.sh, check cluster existence BEFORE calling preflight_checks, and pass a flag or set a variable (e.g., SKIP_PORT_CHECK=true) that preflight_checks respects. Alternatively, move the port check into the bootstrap flow itself -- only check ports if cluster does NOT already exist. Choose the cleanest approach.

CRITICAL: run_cmd must NOT swallow the output of commands whose output is needed for variable capture (like docker network inspect for CIDR). The CIDR extraction command should NOT go through run_cmd -- it needs its stdout. Only use run_cmd for commands where the output is purely informational (kind create, kubectl wait, kubectl apply).
  </action>

  <action>

Source common.sh using the same SCRIPT_DIR pattern as bootstrap.sh.

Define a `usage()` function showing: "Usage: teardown.sh [--clean] [--verbose|-v] [-h|--help]" with description of --clean flag (removes external state like KIND Docker network, sealing key backups, generated configs).

Main flow:
1. `parse_args "$@"`
2. Start elapsed timer: `SECONDS=0`
3. **Cluster deletion (idempotent):** Check `kind get clusters 2>/dev/null | grep -q "^${CLUSTER_NAME}$"`. If exists: `log_step "Deleting cluster..."`, run `kind delete cluster --name "${CLUSTER_NAME}"` via `run_cmd`, log success. If not: `log_info "No cluster '${CLUSTER_NAME}' found, nothing to delete"`.
4. **Clean mode (if --clean):** If CLEAN is true:
   - `log_step "Cleaning external state..."`
   - Remove KIND Docker network: `if docker network inspect kind >/dev/null 2>&1; then docker network rm kind 2>/dev/null || true; log_info "Removed 'kind' Docker network"; fi`
   - Placeholder comments for future phases: "# Remove sealing key backups (Phase 5)", "# Remove generated configs (future phases)"
   - `log_info "External state cleaned"`
5. Print elapsed time: `log_info "Teardown complete in ${SECONDS}s"`

NOTE: teardown.sh does NOT run preflight_checks (no need to check Docker/kind/kubectl exhaustively for deletion -- if tools are missing, the commands will fail with clear errors anyway). However, it does need `kind` to be available. Add a minimal check: if `command -v kind` fails, log_error and exit 1. Docker must also be running for `kind delete` to work -- check `docker info` briefly.
