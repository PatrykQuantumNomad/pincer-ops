**networkpolicy.yaml** -- LiteLLM-specific allow rules (follows openclaw-allow pattern exactly):
- `apiVersion: networking.k8s.io/v1`, `kind: NetworkPolicy`, name `litellm-proxy-allow`, namespace `nemoclaw`
- `podSelector.matchLabels`: `app.kubernetes.io/name: litellm-proxy` (matches Deployment from Plan 01)
- `policyTypes: [Ingress, Egress]`
- Ingress rule: allow from openclaw namespace on port 4000
  ```yaml
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: openclaw
      ports:
        - protocol: TCP
          port: 4000
  ```
- Egress rules (two separate rules, same pattern as openclaw-allow):
  1. DNS egress to kube-system:
     ```yaml
     - to:
         - namespaceSelector:
             matchLabels:
               kubernetes.io/metadata.name: kube-system
       ports:
         - protocol: UDP
           port: 53
         - protocol: TCP
           port: 53
     ```
  2. HTTPS egress to external LLM APIs (0.0.0.0/0 on port 443 -- standard NetworkPolicy cannot filter by FQDN, per research):
     ```yaml
     - to:
         - ipBlock:
             cidr: 0.0.0.0/0
       ports:
         - protocol: TCP
           port: 443
     ```
- Add header comment explaining the file, why default-deny-all is separate (in infra-nemoclaw), and what each rule allows:
  ```
  # networkpolicy.yaml -- Allow rules for LiteLLM Proxy in nemoclaw namespace.
  #
  # The default-deny-all NetworkPolicy in infrastructure/nemoclaw/ blocks all traffic.
  # This policy selectively opens what LiteLLM needs:
  #   - Ingress: OpenClaw pods (from openclaw namespace) on port 4000
  #   - Egress: DNS resolution via CoreDNS (kube-system, port 53)
  #   - Egress: HTTPS to external LLM APIs (port 443)
  #
  # IMPORTANT: This must be deployed in the same ArgoCD sync as the Deployment.
  # If deny-all activates before allow rules, LiteLLM health probes will fail.
  ```
