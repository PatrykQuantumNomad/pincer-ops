<objective>
Create the registration Job that bridges the GitOps-to-gateway gap by injecting the Phase 30 security policy into the OpenShell gateway's database via `openshell policy set`.

Purpose: The gateway discovers the Sandbox CR via its Kubernetes controller, but this path bypasses gRPC registration -- leaving the sandbox with "no spec." This Job runs `openshell policy set openclaw-sandbox --policy /policy/policy.yaml --wait` after the Sandbox CR syncs, injecting the policy so the supervisor can fetch it via GetSandboxConfig.

Output: A PostSync hook Job manifest wired into the openclaw-sandbox Kustomize base, validated by kustomize build and kubeconform.
</objective>

Create `workloads/openclaw-sandbox/base/registration-job.yaml` -- a Kubernetes Job manifest that:

**Metadata (per POL-02):**
- apiVersion: batch/v1, kind: Job
- name: `openclaw-sandbox-policy-registration`, namespace: `openshell`
- Labels: `app.kubernetes.io/name: openclaw-sandbox-registration`, `app.kubernetes.io/component: policy-registration`
- Annotations:
  - `argocd.argoproj.io/hook: PostSync` -- runs after the Application's Sync phase completes (Sandbox CR is applied). Do NOT add a sync-wave annotation -- PostSync hooks ignore sync waves (per research, Pattern 3).
  - `argocd.argoproj.io/hook-delete-policy: BeforeHookCreation` -- deletes old completed Job before creating new one on re-sync (per POL-04).

**Spec:**
- `backoffLimit: 3` -- retry on transient failures (gateway watch delay, per Pitfall 4)
- `activeDeadlineSeconds: 120` -- total Job timeout
- Pod template:
  - `automountServiceAccountToken: false` -- no K8s API access needed
  - Pod securityContext: `runAsNonRoot: true`, `runAsUser: 1000`, `fsGroup: 1000`, `seccompProfile.type: RuntimeDefault`
  - `restartPolicy: OnFailure`

**Init container (`install-cli`):**
- image: `curlimages/curl:8.12.1`, imagePullPolicy: IfNotPresent
- securityContext: `allowPrivilegeEscalation: false`, `capabilities.drop: ["ALL"]`, `readOnlyRootFilesystem: true`
- command: Download OpenShell CLI v0.0.12 from GitHub Releases (tarball for linux-musl, NOT the install.sh script per research Open Question 2). Extract to /cli shared emptyDir volume.
  ```
  curl -LsSf "https://github.com/NVIDIA/OpenShell/releases/download/v0.0.12/openshell-$(uname -m)-unknown-linux-musl.tar.gz" | tar xz -C /cli
  chmod +x /cli/openshell
  ```
- volumeMounts: `cli-bin` at /cli
- resources: requests 50m/32Mi, limits 200m/64Mi

**Main container (`register-policy`) (per POL-02, POL-03):**
- image: `curlimages/curl:8.12.1`, imagePullPolicy: IfNotPresent
- securityContext: `allowPrivilegeEscalation: false`, `capabilities.drop: ["ALL"]`, `readOnlyRootFilesystem: false` (needs to write CLI config dir under $HOME)
- command script (sh -c):
  1. Scaffold CLI config directory (per research Pattern 2):

     - Copy ca.crt, tls.crt, tls.key from /tls to `$GATEWAY_DIR/mtls/`

     - Write `$HOME/.config/openshell/active_gateway` with `local`
  2. Run registration (per POL-02, POL-05):
     `/cli/openshell policy set openclaw-sandbox --policy /policy/policy.yaml --wait`
     The --policy file points to the ConfigMap mount. The full policy YAML (all static + dynamic sections) ensures idempotent full-replace.
- volumeMounts:
  - `cli-bin` at /cli (readOnly: true)
  - `policy` at /policy (readOnly: true)
  - `tls-client` at /tls (readOnly: true)
- resources: requests 50m/32Mi, limits 200m/128Mi

**Volumes:**

- `policy`: configMap `openshell-sandbox-policy` -- the Phase 30 policy ConfigMap
- `tls-client`: secret `openshell-client-tls` -- mTLS certs from cert-manager (Phase 29)
