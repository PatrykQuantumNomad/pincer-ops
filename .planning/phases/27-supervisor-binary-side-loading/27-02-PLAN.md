**Container securityContext change (SUPV-04, SUPV-05):**
Replace the current container-level securityContext:
```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  allowPrivilegeEscalation: false
  capabilities:
    drop: ["ALL"]
  readOnlyRootFilesystem: true
```
With supervisor-required capabilities:
```yaml
securityContext:
  runAsUser: 0
  allowPrivilegeEscalation: true
  capabilities:
    add: ["NET_ADMIN", "SYS_ADMIN"]
    drop: ["ALL"]
  readOnlyRootFilesystem: true
```
- Remove `runAsNonRoot: true` (supervisor needs root for Landlock/netns)
- Change `runAsUser: 1000` to `runAsUser: 0`
- Change `allowPrivilegeEscalation: false` to `true` (required for seccomp-BPF)
- Add `capabilities.add: ["NET_ADMIN", "SYS_ADMIN"]` (NET_ADMIN for network namespace + veth pair, SYS_ADMIN for Landlock LSM)
- Keep `capabilities.drop: ["ALL"]` (drops everything except explicitly added)
- Keep `readOnlyRootFilesystem: true`

**Pod-level seccompProfile stays unchanged:**
```yaml
seccompProfile:
  type: RuntimeDefault
```
The supervisor applies additional seccomp-BPF restrictions internally via the `seccompiler` crate at exec time. K8s provides the baseline RuntimeDefault.

**Add hostPath volume (SUPV-02):**
Add to the volumes list (after existing volumes):
```yaml
- name: supervisor-bin
  hostPath:
    path: /opt/openshell/bin
    type: Directory
```
Using `type: Directory` (not DirectoryOrCreate) because the DaemonSet at wave 3 will have already created this directory by the time the sandbox at wave 10 starts.

**Add volumeMount to container (SUPV-02):**
Add to the openclaw-gateway container's volumeMounts:
```yaml
- name: supervisor-bin
  mountPath: /opt/openshell/bin
  readOnly: true
```

**Add supervisor gRPC env var (SUPV-06):**
Add to the container env list:
```yaml
- name: OPENSHELL_GRPC_ENDPOINT
  value: "openshell.openshell.svc.cluster.local:8080"
```
This tells the supervisor where to poll for network policies via the gateway's GetSandboxConfig/UpdateConfig gRPC RPCs.

Add a new egress rule to the openclaw-allow NetworkPolicy allowing the sandbox pod to reach the OpenShell gateway for gRPC policy delivery (SUPV-06).

Add this egress rule to the openclaw-allow policy's egress list (between the DNS rule and the LiteLLM rule):
```yaml
    - to:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: openshell
          podSelector:
            matchLabels:
              app.kubernetes.io/name: openshell
      ports:
        - protocol: TCP
          port: 8080
```

This targets the OpenShell gateway pod (label `app.kubernetes.io/name: openshell`) in the openshell namespace on port 8080 (gRPC). The rule uses the same namespace+podSelector conjunction pattern used by the existing LiteLLM egress rule.
