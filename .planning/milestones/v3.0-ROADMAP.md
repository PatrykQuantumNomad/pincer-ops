# Milestone v3.0: OpenShell Removal

**Status:** SHIPPED 2026-03-22
**Phases:** 35-37
**Total Plans:** 6

## Overview

Removed the entire OpenShell stack (gateway, supervisor, agent-sandbox CRD, policy system, TLS chain, registration Job) and restored OpenClaw as a standalone StatefulSet with K8s-native security. This reversal was necessary because the OpenShell gateway's CreateSandbox lifecycle is fundamentally incompatible with GitOps — the gateway requires runtime interaction that cannot be declaratively managed.

## Milestone Summary

**Key Decisions:**

- OpenShell gateway/supervisor architecture is incompatible with GitOps (gateway requires CreateSandbox lifecycle)
- Pure deletion approach for Phase 35 — no modifications to remaining files in first pass
- Preserved cert-manager readiness wait and ClusterIssuer in bootstrap.sh for future TLS
- Used infrastructure AppProject for workload-openclaw (workloads project deleted in Phase 35)
- Removed all LiteLLM/nemoclaw references from ConfigMap and NetworkPolicy for clean v3.0
- Soft-fail for OpenClaw wait in bootstrap — cluster functional without it, ArgoCD will sync
- Removed chown from init container — fsGroup:1000 handles PVC ownership without CAP_CHOWN
- Added controlUi.dangerouslyAllowHostHeaderOriginFallback for non-loopback gateway binding

**Issues Resolved:**

- Init container chown failure due to dropped ALL capabilities — fixed by relying on fsGroup
- Missing controlUi config for --bind lan mode — added dangerouslyAllowHostHeaderOriginFallback
- Phantom workloads.yaml references in setup-repo.sh and test helpers — cleaned up
- bootstrap.bats file counts stale after v3.0 directory changes — updated

**Issues Deferred:**

- SealedSecret placeholder values need real keys sealed post-bootstrap

**Technical Debt Incurred:**

- Using dangerouslyAllowHostHeaderOriginFallback instead of explicit allowedOrigins (acceptable for local dev)
