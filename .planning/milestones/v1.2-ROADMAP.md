# Milestone v1.2: NemoClaw Governance Support

**Status:** SHIPPED 2026-03-20
**Phases:** 18-22
**Total Plans:** 9

## Overview

Add NemoClaw governance layer using LiteLLM Proxy as the inference gateway, route OpenClaw through it for credential isolation, and harden security with K8s-native primitives (PSS, SecurityContext, NetworkPolicy).

## Phases

### Phase 18: NemoClaw Namespace and ArgoCD Wiring

**Depends on**: Nothing (first phase of v1.2)
**Requirements**: GOV-05, GOV-06, SEC-03

  3. `nemoclaw` namespace has Pod Security Standards label `pod-security.kubernetes.io/enforce: restricted` and ArgoCD syncs it successfully

### Phase 19: LiteLLM Proxy Deployment
**Goal**: LiteLLM Proxy is running as the inference gateway in the nemoclaw namespace with credential isolation and network security
**Depends on**: Phase 18
**Requirements**: GOV-01, GOV-02, GOV-03, GOV-04, NET-03
**Success Criteria** (what must be TRUE):
  1. LiteLLM Deployment is running with health probes passing in `nemoclaw` namespace
  2. LiteLLM Service exposes port 4000 as ClusterIP and is reachable from within the cluster
  3. LiteLLM ConfigMap provides model routing configuration for NVIDIA NIM, OpenAI, and Anthropic providers
  4. NVIDIA_API_KEY is managed as a SealedSecret and mounted only in the LiteLLM pod (not accessible from other namespaces)
  5. LiteLLM NetworkPolicy enforces default-deny with allow rules for ingress from openclaw namespace, DNS egress, and HTTPS egress to LLM APIs

### Phase 20: Security Hardening
**Goal**: Both OpenClaw and LiteLLM pods run with minimal privileges, and namespace-level security policies are enforced
**Depends on**: Phase 19

### Phase 21: OpenClaw Integration and Network Cutover
**Goal**: OpenClaw routes all inference through the LiteLLM governance proxy and can no longer directly reach LLM APIs
**Depends on**: Phase 19, Phase 20
**Requirements**: INT-01, INT-02, NET-01, NET-02
**Success Criteria** (what must be TRUE):
  1. OpenClaw `openclaw.json` ConfigMap has `models.providers` with `baseUrl` pointing to `http://litellm-proxy.nemoclaw.svc.cluster.local:4000/v1`
  2. OpenClaw pod does NOT have NVIDIA_API_KEY as an environment variable -- credential isolation is enforced
  3. OpenClaw NetworkPolicy allows egress to LiteLLM proxy in nemoclaw namespace on port 4000
  4. OpenClaw NetworkPolicy restricts direct HTTPS egress (443) to messaging platforms only -- direct LLM API access is blocked

## Milestone Summary

**Key Decisions:**
- Governance-only NemoClaw (no sandbox) -- OpenShell sandbox runs K3s internally, cannot nest K8s in KIND
- LiteLLM Proxy replaces non-existent standalone OpenShell governance images
- K8s-native security replaces sandbox layers (NetworkPolicy, PSS, SecurityContext)
- OpenClaw routes inference via `models.providers` baseUrl in openclaw.json (NOT env vars)
- NVIDIA_API_KEY only in LiteLLM pod, not in OpenClaw -- credential isolation
- openclaw namespace gets PSS audit+warn only (not enforce) -- initContainer runs as root
- LiteLLM readOnlyRootFilesystem intentionally left false -- not feasible for LiteLLM runtime
- HTTPS 443 egress retained -- credential isolation prevents direct LLM API access, not network filtering
- openai-completions API type (not openai-responses) -- LiteLLM returns 404 on Responses API

**Issues Resolved:**
- Stale bootstrap directory file count tests updated for v1.2 additions
- Existing mock helpers already covered all piped kustomize calls including new targets

**Issues Deferred:**
- LiteLLM stateless operation needs runtime verification (config-file routing without database)
- LiteLLM image size (500MB+ Python image) -- verify fits KIND resource constraints
- OpenClaw config reload behavior -- may require pod restart when updating openclaw.json ConfigMap

**Technical Debt Incurred:**
- LiteLLM readOnlyRootFilesystem left false (runtime constraint)
- SealedSecret placeholder values need real keys sealed post-bootstrap
- FQDN-based egress blocking not possible with standard NetworkPolicy
