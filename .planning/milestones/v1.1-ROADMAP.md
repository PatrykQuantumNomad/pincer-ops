# Milestone v1.1: Kinder Support

**Status:** SHIPPED 2026-03-19
**Phases:** 12-17
**Total Plans:** 12

## Overview

Make Kinder the default cluster provider while maintaining KIND as an opt-in alternative, with full GitOps reproducibility for both providers.

## Phases

### Phase 12: Provider Abstraction Layer

**Goal**: Users can select between Kinder and KIND via a single variable, with correct cluster config applied automatically
**Depends on**: Nothing (first phase of v1.1)
**Plans**: 2 plans

Plans:
- [x] 12-01: Kinder config file + Makefile CLUSTER_PROVIDER variable plumbing
- [x] 12-02: Provider-aware preflight checks with interactive fallback

**Details:**
- Created `cluster/kinder-config.yaml` with identical topology to KIND (1 CP + 2 workers, ports 80/443) plus Kinder-specific addons
- Added CLUSTER_PROVIDER variable (default: kinder) with derived PROVIDER_BIN and PROVIDER_CONFIG to Makefile
- `check_provider()` function in common.sh with kinder/kind detection, interactive TTY fallback, and explicit-selection hard-fail
- All provider-aware targets propagate provider selection

### Phase 14: Bootstrap and Teardown Dual-Mode

- [x] 14-02: BATS tests for dual-provider bootstrap and teardown paths

**Details:**

- Steps 13 (Gateway API DaemonSet config), 14 (Sealed Secrets), and 16 (OpenClaw) run for both providers
- 5 new BATS tests for Kinder paths; existing tests pinned to CLUSTER_PROVIDER=kind for regression safety

## Milestone Summary

**Key Decisions:**
- Kinder is default provider, KIND is opt-in via CLUSTER_PROVIDER=kind
- Kinder-provided infra (MetalLB, Envoy GW controller, cert-manager) skips ArgoCD management
- Provider-specific directory scanning: root-app scans bootstrap/kind/ or bootstrap/kinder/
- Shared files duplicated (byte-identical) across provider directories rather than symlinks
- CLUSTER_PROVIDER set non-readonly before preflight, locked readonly after (supports check_provider fallback)

**Issues Resolved:**
- Bootstrap fallback path for repo-unreachable scenarios (idempotent AppProject/argocd-self application)
- SIGPIPE race condition in all operational scripts (variable-capture pattern)
- Stale wave -4 dependency comment in shared bootstrap files
- Makefile env propagation gap for setup-mcp and verify-netpol targets

**Issues Deferred:**
- argocd-self/root circular dependency: Cosmetic Progressing/OutOfSync (accepted, does not affect operations — carried from v1.0)

**Technical Debt Incurred:**
- None — Phase 17 closed all tech debt identified by audit
