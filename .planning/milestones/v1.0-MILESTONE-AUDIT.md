## Tech Debt

### Phase 8: Reproducibility Verification

1. **Stale comments (4 instances):** `bootstrap.sh` lines 134, 194, 214 and `infra-envoy-gateway-config.yaml` line 10 reference "placeholder repoURL" as if still current. Functional log_warn messages are correct; only code comments are stale.

2. **Unconditional direct-apply for envoy-gateway-config:** bootstrap.sh Step 13 always applies Gateway API config via kustomize without trying ArgoCD first. Other components (MetalLB, Sealed Secrets, cert-manager, OpenClaw) poll for ArgoCD sync and fall back on ComparisonError. Step 13 was kept unconditional due to CRD timing sensitivity. ArgoCD reconciles via selfHeal afterward.

### Phase 9: Operational Maturity

3. **Placeholder webhook URL:** `argocd-notifications-cm.yaml` targets `http://localhost:9999/webhook`. One-line swap for production.

4. **hostPath backup storage:** Both PVC backup and sealing key backup CronJobs use hostPath volumes. Backups lost on KIND teardown. Acceptable for local dev.

5. **Manual pre-commit hook installation:** Developer must run `scripts/hooks/install-hooks.sh` manually. Not automated by bootstrap.sh (bootstrap is cluster infrastructure, not developer workstation setup).

### Phase 7: Network Security

6. **Runtime verification pending:** 4 NetworkPolicy checks (DNS resolution, HTTPS egress, ingress path, deny enforcement) verified statically but need live cluster for full runtime confirmation. These were verified as passing during Phase 6/7 execution but the verifier could not re-run them from codebase inspection.

### Accepted Known Issues

7. **argocd-self/root Progressing:** Circular self-management dependency causes both meta-Applications to show Progressing/OutOfSync permanently. All actual resources are Healthy. Cosmetic issue accepted in Phase 8.

## Conclusion

The v1.0 milestone is feature-complete with no critical blockers. All 33 requirements are met. Cross-phase integration is fully wired. The accumulated tech debt consists of documentation cleanup (stale comments), dev-environment limitations (placeholder webhook, hostPath backups), and one bootstrap purity item (unconditional direct-apply). None of these affect cluster functionality or the GitOps contract.

**Recommendation:** Proceed with milestone completion. Track tech debt items as candidates for v1.1 cleanup phase.
