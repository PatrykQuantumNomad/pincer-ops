## v2.0 Requirements

Requirements for v2.0 OpenShell Sandbox milestone. Each maps to roadmap phases.

### Infrastructure Foundation

- [x] **INFRA-01**: `openshell` namespace created with PSS `privileged` label and ArgoCD tracking -- Phase 23
- [x] **INFRA-02**: `agent-sandbox-system` namespace created with PSS `restricted` label -- Phase 23
- [x] **INFRA-03**: ArgoCD AppProjects updated with openshell and agent-sandbox-system destinations -- Phase 23
- [x] **INFRA-04**: `make doctor` checks Landlock kernel support on KIND nodes (`/sys/kernel/security/lsm`) -- Phase 23
- [x] **INFRA-05**: Bootstrap script updated with TLS generation and new namespace creation steps -- Phase 23

### Sandbox Runtime

- [x] **SAND-01**: Agent-sandbox CRD controller deployed as ArgoCD Application (wave 2, SSA=true) -- Phase 24
- [x] **SAND-02**: Sandbox CRD (`sandboxes.agents.x-k8s.io/v1alpha1`) registered and operational -- Phase 24
- [x] **SAND-03**: Custom Lua health check for Sandbox resource type added to argocd-cm -- Phase 24
- [x] **SAND-04**: OpenShell gateway deployed as StatefulSet (wave 5) with SQLite PVC -- Phase 25
- [x] **SAND-05**: Gateway RBAC: Role (Sandbox CRUD in openshell ns) + ClusterRole (nodes, runtimeclasses) -- Phase 25
- [x] **SAND-06**: Gateway Service (ClusterIP:8080) exposed for sandbox gRPC communication -- Phase 25
- [x] **SAND-07**: Gateway TLS disabled via env vars for dev (OPENSHELL_DISABLE_TLS, OPENSHELL_DISABLE_GATEWAY_AUTH) -- Phase 25
- [x] **SAND-08**: Gateway manifests pre-rendered from Helm chart as static Kustomize YAML -- Phase 25

### OpenClaw Migration

- [x] **MIGR-01**: OpenClaw runs as static Sandbox CR managed by ArgoCD (wave 10) -- Phase 26
- [x] **MIGR-02**: Agent-sandbox controller reconciles Sandbox CR into Pod with stable hostname and PVC -- Phase 26
- [x] **MIGR-03**: HTTPRoute updated to target Sandbox pod Service in openshell namespace -- Phase 26
- [x] **MIGR-04**: Old `workload-openclaw` ArgoCD Application removed -- Phase 26
- [x] **MIGR-05**: Old `openclaw` namespace and orphaned PVC cleaned up -- Phase 26
- [x] **MIGR-06**: OpenClaw accessible via localhost:80 through Envoy Gateway after migration -- Phase 26
- [x] **MIGR-07**: OpenClaw `NetworkPolicyManagement: "Unmanaged"` with our own NetworkPolicy rules -- Phase 26

### Supervisor + Isolation

- [x] **SUPV-01**: Supervisor binary DaemonSet deploys `openshell-sandbox` to `/opt/openshell/bin/` on all nodes -- Phase 27
- [x] **SUPV-02**: Sandbox CR podTemplate mounts hostPath volume for supervisor binary -- Phase 27
- [x] **SUPV-03**: Supervisor runs as PID 1 inside sandbox pod enforcing Landlock filesystem restrictions -- Phase 27
- [x] **SUPV-04**: Supervisor enforces seccomp-BPF custom syscall filtering -- Phase 27
- [x] **SUPV-05**: Supervisor creates network namespace with veth pair and HTTP CONNECT proxy -- Phase 27
- [x] **SUPV-06**: OpenShell network policy YAML (per-binary, per-endpoint) delivered via gateway gRPC -- Phase 27

### Inference Routing

- [x] **INFER-01**: Privacy router intercepts `inference.local` calls from sandbox and routes to configured providers -- Phase 28
- [x] **INFER-02**: Provider credentials configured via OpenShell gateway (not K8s Secret in sandbox pod) -- Phase 28
- [x] **INFER-03**: LiteLLM Proxy Application removed after privacy router verified end-to-end -- Phase 28
- [x] **INFER-04**: `nemoclaw` namespace fully cleaned up (all LiteLLM resources, SealedSecret) -- Phase 28

### Security Hardening

- [x] **SEC-01**: mTLS enabled between gateway and sandbox pods via cert-manager -- Phase 29
- [x] **SEC-02**: TLS certificates stored as SealedSecrets for Git-safe management -- Phase 29
- [x] **SEC-03**: NetworkPolicy retained as belt-and-suspenders alongside supervisor proxy -- Phase 29
- [x] **SEC-04**: Sandbox pods accept only SSH ingress (port 2222) from gateway pod -- Phase 29

### Testing & Validation

- [x] **TEST-01**: BATS structural tests for all new OpenShell/agent-sandbox manifests -- Phase 29
- [x] **TEST-02**: kubeconform CI validation with CRD schema for `agents.x-k8s.io/v1alpha1` -- Phase 29
- [x] **TEST-03**: Both Kinder and KIND providers pass full `make check` -- Phase 29
- [x] **TEST-04**: Bootstrap/teardown cycle produces operational state with OpenShell stack -- Phase 29
- [x] **TEST-05**: Dual-provider bootstrap directory pattern (byte-identical shared files) -- Phase 29
